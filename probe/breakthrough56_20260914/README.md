## 实际实现和结果

483–490 使用独占 Donau 作业 `1604520`，目录 `/home/share/niujiayin/trsm-breakthrough56-20260914`。
生产基线原始 bench 三轮中位为 TC1 2726.2124、TC2 4250.1314 GFLOPS（483）。
以下是配置筛选中的最佳结果，通常是单进程三个计时调用的均值，**不是交错复验后的稳定成绩**。
完整慢轮与首次调用 profile 都保留。

| 实验 | 改变的算法/数据流 | TC2 最快筛选 GFLOPS | 判断 |
|---|---|---:|---|
| 483 | 每次完整求逆，再做无前代依赖的三角前缀乘法 | 1473.74 | 远慢于现有实现 |
| 485 | 同一全逆算法，改为缓存分块的应用与分块 RHS 打包 | 2433.43 | 修复部分供数开销，仍未接近基线 |
| 486 | 解出一块后立即更新所有剩余 RHS，即右看式求解 | 2063.58 | 对角子调用、打包和全局更新开销过大 |
| 487 | RHS 全程在连续内部面板中，逐调用预求各对角块的逆 | 1864.78 | 省去部分跨行访问，但求逆和更新仍很慢 |
| 489 | 局部逆改为递归 SME 乘法，并比较更新循环次序 | 1581.30 | TC3 最快 1758.76；仍慢于基线 |

483 的 NC128 profile：暖调用求逆约 5.7 ms、打包约 6.6 ms、乘法约 96.6 ms，总计约 109 ms。
NC32 更快，但仍在 68–70 ms 左右。485 的 NC128/KC128 将乘法降到约 31.7 ms、打包降到约 3.7 ms，
总计仍约 41.2 ms。这反驳的是当前原型的收益，不是所有求逆算法的上界。

TC3 的右看式原型最快约 1620.09 GFLOPS，连续 RHS 加局部逆原型约 1944.28 GFLOPS，
均远低于现有实现。TC1 上 NB512 的右看式调用只有一个对角块，实质上仍调用原求解器；不能把它当作新算法有效的证据。

## INT8 路线：减少编码副本与重构工作

484 新写了平衡数位卷积原型。输入是独立 53 位数值、全正和正负交替数据，不取官方生成器的格子、种子或状态。
每次测量重新编码 A/B，计算截断卷积并重构 FP64 输出。
除了普通数位卷积，还测试了 `(Ai+Aj)(Bi+Bj)-AiBi-AjBj` 的成对乘积重组。

| 配置 | 512×512×2048，38 线程最佳配置的三次中位 GFLOPS，含编码 |
|---|---:|
| 5 个基 256 数位，Q39，15 次整数乘积 | 666.273 |
| 6 个基 256 数位，Q47，21 次整数乘积 | 579.184 |
| 7 个基 128 数位，Q48，成对重组 19 次乘积 | 444.893 |
| 488 的同输入 FP64 产品对照，最佳配置 | 860.436 |

FP64 对照和量化原型均不是高度调优的 GEMM，不能把它们的分数等同完整 TRSM 的性能；FP64 大矩阵只有 16 个输出任务，未充分使用 38 核。
该比较仍足以说明本轮的转换、整数乘积和重构组合没有展现优势；不要只引用 INT8 峰值。
小矩阵逐个检查全部 1024 输出，大矩阵仅检查 64 个独立坐标。量化组件的误差界包括输入量化和截断项，
但**尚无完整 TRSM 的误差传播保护**，组件 PASS 不能当作正式求解器精度认证。

490 请求本进程允许的最大 SVE/SME 向量长度后均返回 64 字节（512 位），与当前内核一致；
没有遗漏更长向量这一条硬件捷径。进程随后恢复原设置，没有修改系统配置。
