基线固定为 `3b24f38:trsm.c`（v53），SHA256 为
`dc8c8b4907c37362bd4d3d108dd4a9e35474736e7570091e7a2b2a79dd84f294`。
最终任务生成候选为 `generated/trsm-implicit-final.c`，SHA256 为
`936704cb25f79f9b497e33e1e9ba7ceaa972173421dd3863be049fb673dc0589`。

## 机制与范围

TC1 的 owner 任务原来每次完整填写 1664 个结构体，再遍历代价以划分线程边界。
任务编号 `q` 已能确定面板 `q/nrb` 和行块 `q%nrb`，其余字段由当前块参数确定。
候选每次调用用累计代价公式加二分查找重算线程边界，执行时生成当前任务和下一任务的临时结构体。
它消除了完整任务表的填写与读取，不保留上一次调用的任务或边界。
每个线程的执行顺序、矩阵数据处理以及 FP64 内核保持 v53 行为。

默认开启 `TRSM_IMPLICIT_OWNER=1`，设为 0 可在同一二进制内比较原路径。
门控为 owner 专用路径、`m<=1024`、`MB/NC/KC=64/96/64`、完整行块和面板、无 CSHIFT/PPMODE/KHEADW，且代价权重非负。
其他尺寸和配置走原任务表构建。不是按输入数值挑选算法，也没有随机数生成器推断。

## 环境与方法

2026-09-13，鲲鹏 72F5 计算节点，HPCKit 26.1.RC1 的 GCC 12.3.1 与 KML multi。
编译使用 `-O3 -march=armv9-a+sme+sme-f64f64+sve2 -fopenmp`；官方 benchmark 原样链接 `-lm -lkblas`。
性能测试均为 38 线程、NUMA1、优先 HBM17。独立数值测试另覆盖 1、5 和 38 线程。
作业独占节点，使用自己的目录与队列，不修改 PAC 的程序和作业。

每轮交错运行 v53、候选和候选关闭开关，偶数轮反向；最终性能测试每进程 11 次计时。
报告全部进程结果的中位数以及同轮比值的几何平均，不删除慢轮。
`summary.csv` 的 bootstrap 区间只是本次轮次的描述性不确定性，不能当作线上成绩或跨所有节点的保证。
初筛原型和最终源码的结果分别记录；profile 含插桩开销，不拿它的分数选型。

TC2/3 门控关闭，继续原路径；上述小幅波动不能当作这两例算法取得进展。

435 的 profile 中，按编号生成任务将每线程 prep 平均由约 0.028 降到 0.020 ms。
最终 443 的 profile 波动较大，不能据此声称 prep 必然节省固定时间；此组 load 约 0.307→0.301 ms，kloop 约 1.01 ms 基本相同。
因此实际取舍依赖未插桩的官方多节点测试。

438 对角求逆原型的组件时间约 24.30→20.45 ms（2048 次整个预处理函数），TC3 的 prep 约 0.419→0.375 ms，
但完整求解中只得到约 +0.3%～+0.5%。这不能解决 TC2/3 的大幅性能差距；没有将该原型混入最终源码。
严格差异诊断为：默认编译时 mode1 出现约 1 ULP 差异；`-ffp-contract=off` 下 mode0/1 各 706560 个元素逐位相同。
正常编译的组件检查使用 `256*DBL_EPSILON*绝对乘积和 + 1e-300`，各模式通过；这不是完整 TRSM 的 1e-12 已知解验证，不能混用结论。

## 正确性与合规证据

最终源码及其仅加断言/计数的副本通过：

- 原/新任务字段与线程边界比较：1800 种配置、1279080 个任务、51840 个边界。
- 84 组通用正确性比较，包含不同尺寸、非对齐和填充区保护。
- 192 组独立长双精度构造的已知解，包含符号、1e100/1e-100 缩放与同址新旧路径切换。
- 12 次正式尺寸同地址重新生成输入；32 组开关/门控边界检查，包含 m=1024/1088、非整面板、1/38 线程以及串行/并行建表。
- 逐调用审计：每例四次调用分别为初始、完全相同输入、修改一个 L 元素并更新 RHS、仅改变 RHS。每次都完整预处理当前输入。
- 原样 `run.sh` 在独立提交目录中编译并通过三例；另按 `numactl -N 1` 原样运行三例。生产 ARM 对象唯一全局导出定义为 `l_trsm`；无 SME 的本地编译通过。

| 测例 | 每次建表入口次数 | 每次重新计算 owner 边界次数 | 每次对角子块数 | 每次非空 L 打包条数 | 四次最大误差 |

规则依据是初始 README（`be3667ca`）与用户补充要求。生产修改范围只有 `trsm.c`；benchmark 与 run.sh 保持 v53 字节不变。
`bench_trsm.c` 与初始 Git blob `a16843e2c49f16fa5b76ce6cd0c6f739c06b42ab` 一致。
没有修改计时、精度阈值、BLAS/校验接口；没有低精度格点推断、输入页迁移或忙核探测。
